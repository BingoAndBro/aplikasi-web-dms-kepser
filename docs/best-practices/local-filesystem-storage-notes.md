# Local Filesystem Storage Notes

## Storage Location

Store uploaded files under `storage/`, outside public/static folders. Do not configure the web framework, reverse proxy, or static middleware to serve `storage/` directly.

Recommended separation:

- `storage/temp/` for pending uploads.
- `storage/documents/` for formal document files.

## API-Only Access

Preview and download must go through API routes:

1. Authenticate request.
2. Authorize user/active role for the document.
3. Resolve file metadata from DB.
4. Resolve the safe filesystem path.
5. Stream the file with appropriate headers.

Never trust a user-provided raw path.

## Path Traversal Prevention

Path traversal attacks use values such as `../` or absolute paths to read files outside the intended directory. Prevent this by:

- Storing canonical relative paths generated by the server.
- Rejecting absolute paths.
- Normalizing and resolving paths before access.
- Verifying the resolved path remains inside the configured storage root.
- Never joining unchecked request parameters directly into filesystem paths.

## MIME And Extension Validation

Use allowlists for accepted document types. Validate:

- Extension.
- Declared content type.
- File signature where practical.
- File size.

Do not rely only on user-supplied filenames or `Content-Type` headers.

## File Size Limits

Set limits for:

- Per-file upload size.
- Total files per document.
- Total request body size.
- Preview/download streaming behavior.

Limits should be explicit env/config values, not scattered magic numbers.

## Signed-Token Preview/Download

Preview/download uses internal signed-token behavior (`src/lib/storage/file-access-token.ts`):

- Token identifies document/file access intent.
- Token has short expiry.
- Token is signed with a server-only secret.
- Endpoint still revalidates authorization where required.
- Token does not expose storage path details unnecessarily.

Token format is implemented in `src/lib/storage/file-access-token.ts`; change it only together with its tests.

## Backup Alignment

Database and filesystem must be backed up together. If DB points to files that are missing, preview/download breaks. If files exist without DB metadata, cleanup behavior must decide whether they are orphaned.

Backup set should include:

- PostgreSQL dump.
- `storage/` archive.
- Timestamp metadata.
- App version or migration version.

Restore validation should include opening at least one document preview/download from each relevant workflow state.
